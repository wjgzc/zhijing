# 知径

鸿蒙学习应用，提供小学数学和 Java 数据结构两门课程，包含知识图谱、练习判题、学习助手、学习路径和桌面待办卡片。

本仓库整理为**软件运行版本**：应用工程、后端源码、两门课程的运行模型、题库与配图均随仓库提供。不需要研究目录、原始学生提交或数据库，也不需要重新训练模型才能启动。

完整功能与操作步骤见 [知径产品介绍与使用说明](知径产品介绍与使用说明.md)。

## 先分清：打开 App 与自建后端

**继续使用现有软件时，只需打开鸿蒙工程。App 保留现有云后端地址；Java 判题、学习诊断以及 AI API 调用仍在云服务器运行。手机不需要安装 Java、Python、Docker，也不填写 AI 密钥。**

```text
鸿蒙 App → 现有云后端 → 题库／模型、Java 隔离判题、AI 服务
```

第 1 节是正常打开和构建 App 的步骤。第 2～4 节仅供维护者在另一台服务器重新部署后端时参考，现有云服务器无需因本次 GitHub 上传重新部署或更改配置。

## 1. 打开鸿蒙工程

1. 克隆本仓库或下载完整源码，保留目录结构。
2. 使用支持 HarmonyOS 6.0.2（API 22）的 DevEco Studio 打开仓库根目录。
3. 安装相应 SDK，让 IDE 同步 OHPM 依赖并生成本机的 `local.properties`。
4. 构建 `entry` 模块。
5. 在真实设备上运行时，在 DevEco Studio 中配置你自己的自动签名及设备，然后运行。

仓库的 `build-profile.json5` 不含个人证书路径或签名密码，因此可以先进行无签名构建；安装到设备需要本机签名。不要把 IDE 后来填入的签名材料提交到 GitHub。

应用目前保留现有在线后端地址，因此构建后的页面沿用原使用方式。在线服务可用性仍取决于该服务；如果使用自建后端，在 `entry/src/main/ets/services/BackendService.ets` 的 `BACKEND_BASE_URL` 中填写手机实际能访问到的地址，再重新构建。

手机上的 `127.0.0.1` 指手机自身，不能用它访问电脑的本地服务。开发时可以使用电脑局域网地址，前提是设备能互通并且只在受控网络开放服务端口。正式部署应使用 HTTPS，并对 AI 和判题入口配置访问控制与限流。

## 2. 可选：在另一台机器启动自己的后端

使用 Python 3.11 或更新版本。首次运行需联网安装依赖，之后的题库、模型和配图不需要从研究资料重新生成。

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r server/requirements.txt
python scripts/check-runtime.py
python scripts/run-backend.py
```

macOS / Linux：

```bash
source .venv/bin/activate
python -m pip install -r server/requirements.txt
python scripts/check-runtime.py
python scripts/run-backend.py
```

启动后访问 `http://127.0.0.1:8000/health`，应能看到数学 865 个模型位置和数据结构 96 个模型位置。API 说明在 `http://127.0.0.1:8000/docs`。

默认仅监听本机。局域网开发需要显式指定：

```bash
python scripts/run-backend.py --host 0.0.0.0 --port 8000
```

本项目不需要数据库。后端启动会从仓库中的模型和 JSON 加载课程，不读取 `HarmonyOS-KT/`、学生原始提交、研究预测缓存或论文材料。

## 3. 可选：为自建后端启用学习助手

把 `server/.env.example` 复制成 `server/.env`，在本机私有文件中填写自己的 DeepSeek API 密钥：

```dotenv
DEEPSEEK_API_KEY=在这里填写自己的密钥
```

使用实际密钥替换中文说明，不要加引号或把说明文字原样保留。重启后端后生效。也可通过进程环境变量配置。

未配置密钥时，题库读取、数学判分和模型预测仍可运行；AI 聊天会提示服务未配置，不会伪造回答。本仓库不附赠任何私人 API 密钥。

`server/.env` 被 Git 忽略，不要把它放入截图、日志或提交。AI 调用可能产生你自己账户的费用。

## 4. 可选：为自建后端启用 Java 判题

Java 用户代码始终在隔离容器中运行，不在 API 进程或宿主直接执行。Windows 上可在 Linux 服务器或配置好的 WSL2 Linux 环境启动整套后端；没有容器服务时，题目仍可读取，但 Java 提交返回服务不可用。

### Podman

在 Linux 上安装并配置 Podman，使运行账户具备创建容器的权限，然后在仓库根目录执行：

```bash
podman build -t localhost/zhijing-java:17 -f server/Containerfile.java .
python scripts/run-backend.py --with-judge
```

首次构建镜像需要联网拉取官方 Eclipse Temurin Java 17 基础镜像。提交代码的容器本身禁网，使用非特权用户、只读根文件系统和临时工作区，并限制内存、CPU、进程数、运行时长和输出量。

### Docker

使用配置正常的 Linux Docker 环境时：

```bash
docker build -t zhijing-java:17 -f server/Containerfile.java .
export JAVA_CONTAINER_ENGINE=docker
export JAVA_JUDGE_IMAGE=zhijing-java:17
python scripts/run-backend.py --with-judge
```

启动器会为 API 和本机 `127.0.0.1:8001` 的独立判题进程生成共享随机令牌，保存在进程环境中，不写进仓库，也不打印令牌。按 Ctrl+C 退出启动器会结束它启动的两个进程。

如果自行通过进程管理器启动两个服务，须给它们配置相同且至少 32 字符的私有 `JUDGE_TOKEN`。不要开放判题进程的 8001 端口到公网。

## 5. 验证运行版本

只检查题库、模型和配图是否完整，不启动服务：

```bash
python scripts/check-runtime.py
```

检查实际 HTTP 启动、双课程读取、数学判题、预测和图片返回：

```bash
python scripts/check-runtime.py --live
```

该检查临时监听随机本机端口并在结束后停止自己启动的进程，不调用付费 AI，也不执行 Java 用户代码。它不能代替下面的容器检查或设备验收。

配置 Linux 判题环境后，可执行真实容器检查：

```bash
python server/tests/check_java_sandbox.py
```

鸿蒙构建后，可使用系统 Node.js 和 DevEco SDK 中的 TypeScript 模块运行已有状态回归脚本；最后一个参数替换为自己的 SDK 实际路径：

```bash
node scripts/test-study-state.cjs /path/to/typescript
node scripts/test-home-sync.cjs /path/to/typescript
node scripts/test-agent-suggestions.cjs /path/to/typescript
node scripts/test-java-submission.cjs /path/to/typescript
node scripts/test-native-widget.cjs /path/to/typescript
```

部分脚本读取 ArkTS 构建生成文件，因此必须先成功构建。桌面卡片添加、刷新、最新弹层和深色外观还需真机检查。

## 6. 运行数据与安全边界

- 仓库只保留推理需要的两份模型、题目、知识点映射和题目图片，不包含学生原始作答或研究训练表。
- 题目数据包含判题所需答案和测试，服务接口在适当阶段隐藏这些字段；源码仓库里的服务端题库本身并不保密，不适合作为必须保密的正式考试题库。
- 应用学习记录保存在设备本地，服务端请求会包含当前操作所需的题目答案、代码或对话。
- 现有接口未实现用户登录鉴权。对公网部署前，应在网关落实 HTTPS、鉴权、速率与费用保护；单纯拥有容器隔离不代表 AI 入口不会被滥用。
- 不上传 `.env`、SSH 私钥、证书、签名密码、设备授权文件和包含敏感信息的打包产物。
- 发布前执行 `python scripts/check-publish.py`。它检查当前 Git 候选文件，并且不打印匹配到的密钥值。
- 此次清理只保证本次发布内容的检查范围。旧 Git 提交曾含 API 密钥及签名配置：普通新提交不会删除旧历史；持有人应撤销或轮换旧密钥。历史重写需单独协调，不能代替密钥失效。
